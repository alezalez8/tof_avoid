# CLAUDE.md — tof_avoid

Модуль обнаружения препятствий: STM32F4 + 3 × VL53L8CX (Pololu #3419, SPI) → один виртуальный
proximity-сенсор `OBSTACLE_DISTANCE` по MAVLink 2 → Cube Orange+ (ArduCopter 4.7.2, штатный BendyRuler).
Отвечай и пиши отчёты по-русски; идентификаторы, комментарии в коде и сообщения коммитов — по-английски.

## 1. Источник истины

- `docs/TZ_3.1.md` — окончательное ТЗ. Требования имеют ID (SNS, MAP, ICD, FLT, FC, SPD, DIA, SW, HW),
  тесты — T-00…T-27, этапы — E0…E8, гипотезы — H-01…H-14.
- Перед любой задачей читай разделы ТЗ, к которым она относится. Не полагайся на память о ТЗ.
- **Ты не меняешь требования.** Если требование противоречиво, невыполнимо или неясно — не выдумывай:
  запиши в `docs/deviations.md` (ID, суть, варианты, твоя рекомендация) и спроси человека.
- Значения с пометкой «параметр» берутся из раздела 15 ТЗ и живут в таблице параметров, не в коде.

## 2. Этапы и что тебе можно сейчас

| Этап | Нужно железо | Статус для тебя |
| --- | --- | --- |
| E0 Каркас, E1 Ядро, E3 SITL | Нет | Выполняешь самостоятельно |
| E2 Плата | Модель платы от человека | Только после того, как человек дал данные о плате |
| E4–E6 Датчики, HIL | Плата, датчики, Cube на столе | Только по явной команде человека «плата подключена» |
| E7 Стенд, E8 Полёт | Человек | Ты обрабатываешь логи и готовишь отчёты |

- Не переходи к следующему этапу, пока не закрыта точка принятия решения текущего (раздел 14 ТЗ).
- Модель платы неизвестна (`BOARD` не задан). До E2 не создавай пин-аут, CubeMX-проект и `bsp/<board>/`;
  target-сборка до E2 — только `target-check`: `core/` как статическая библиотека для Cortex-M4F
  тулчейном CubeCLT (проверка тулчейна и FPU-кода, без привязки к плате).

## 3. Окружение

- Хост — Windows, VS Code + Claude Code. Репозиторий: `D:\stm32\tof_avoid` (в WSL — `/mnt/d/stm32/tof_avoid`).
- **Host-сборка, юнит-тесты, покрытие, эмулятор, SITL — в WSL2 Ubuntu** (gcc, cmake, ninja, gcovr, python3, pymavlink).
  Вызов из Windows: `wsl -e bash -lc "cd /mnt/d/stm32/tof_avoid && <команда>"`.
- **Target-сборка — на Windows через STM32CubeCLT** (arm-none-eabi-gcc, CMake, Ninja), прошивка —
  `STM32_Programmer_CLI` через ST-Link, отладка — Cortex-Debug.
- ArduCopter 4.7.2 SITL уже собран в WSL2. Путь к дереву ArduPilot и команду запуска SITL зафиксируй
  в `docs/env/<имя_компьютера>.md` при первом запуске на этой машине (найди сам; если не найдёшь — спроси).
- Если чего-то из окружения нет — проверь (`which`, `--version`), предложи команду установки и спроси.
- **Работа на нескольких компьютерах.** Проект ведётся на двух машинах через приватный git remote.
  В начале сессии: `git pull` (и `git submodule update --init --recursive`); в конце: коммит и `git push`.
  Окружение у машин разное: записывай его в `docs/env/<имя_компьютера>.md` (имя — `hostname`),
  а скрипты пиши без жёстких путей к тулчейнам — бери их из PATH или из `docs/env`-независимых переменных.
  Каталоги сборки, venv и логи SITL — в `.gitignore`. Скрипты `.sh` — с LF (`.gitattributes`: `*.sh text eol=lf`).

## 4. Структура репозитория (SW, раздел 11 ТЗ)

```

               fault_fsm, events, params, scheduler
bsp/           bsp.h — единственный интерфейс к железу; bsp/<board>/ — после E2
drivers/       vl53l8cx_platform.c (ULD через bsp), lcd_<model>.c
third_party/   ST ULD (без изменений), mavlink/c_library_v2 (submodule), Unity
app/           main.c, сборки DEBUG и FLIGHT
tests/host/    юнит-тесты ядра (Unity + CTest)
tools/         emulator/ (pymavlink + SITL-сценарии), logdecode/, scripts/
params/        fc_tof_v1.param (параметры FC), module_defaults.json
docs/          TZ_3.1.md, env/<hostname>.md, traceability.md, deviations.md, reports/, pinout.md (E2)
```

CMake: пресеты `host-debug`, `host-coverage`, `target-check` (до E2), после E2 — `target-<board>-debug`,
`target-<board>-flight`.

## 5. Правила кода

- `core/`: C11, без HAL и без включений из `bsp/`; без `malloc`, рекурсии и VLA; только `float`
  (никаких `double` и `math.h`-функций для double); детерминированность — один вход, один выход на ПК и МК.
- Время передаётся в ядро аргументом (`uint32_t now_us`/`now_ms`), ядро не читает часы само.
- Свой код: `-Wall -Wextra -Werror`; cppcheck без warning. `third_party/` не правится — только обёртки.
- Нет бесконечных ожиданий: каждая операция с железом — с таймаутом (SNS-10); никаких `HAL_MAX_DELAY`.
- Прерывания только ставят флаги и перекладывают данные; основной цикл — кооперативный (SW-05).
- Каждая функция ядра, реализующая требование, имеет комментарий `/* REQ: MAP-13 */`.

## 6. Тесты и трассируемость

- Каждый юнит-тест помечен требованием в имени: `test_MAP13_occupied_holds_on_invalid()`.
- `docs/traceability.md` — таблица «требование → файл/функция → тест → статус (todo/impl/pass)».
  Обновляй её в том же коммите, что и код.
- Готово = код + тесты проходят + покрытие `core/` ≥ 90 % + traceability обновлена. Без этого задача не закрыта.
- Тест ТЗ (T-xx), который ты прогнал, оформляй отчётом `docs/reports/T-xx_<дата>.md`: версия прошивки
  и FC, конфигурация (CRC параметров), шаги, данные, результат против критерия ТЗ, дефекты.

## 7. Безопасность — жёсткие запреты

- Никогда не подключайся по MAVLink к реальному FC, не отправляй команды реальному аппарату
  и не меняй его параметры. С реальным Cube работает только человек; ты готовишь `params/*.param`.
- Модуль отправляет только `DO_SET_MODE` (BRAKE/LOITER по FLT-03…FLT-05) и `SET_MESSAGE_INTERVAL`.
  Никаких других команд движения, arm/disarm, миссий — ни в коде, ни в эмуляторе от имени модуля.
- Не трогай option bytes, защиту чтения, загрузчик; mass erase — только с разрешения человека.
- Прошивку на плату заливаешь только после фразы человека, что плата подключена и моторы/винты не участвуют.
- Не включай `GROUND_POLICY = DROP` и `FAULT_WALL = 1` по умолчанию (MAP-07, MAP-19, FLT-10).
- Не скачивай файлы, требующие логина (ST ULD) — попроси человека положить архив в `third_party/`.

## 8. Ключевые технические факты (частые ошибки)

- ArduPilot (`AP_Proximity_MAV.cpp`, Copter-4.7.2): значения 0, 65535, `< min`, `> max` отбрасываются
  одинаково; каждое `OBSTACLE_DISTANCE` сбрасывает всю границу; `time_usec` не используется;
  таймаут 500 мс → статус NoData. Поэтому **одно сообщение на кадр карты**, а не по одному на датчик.
- Кодирование: `frame = MAV_FRAME_BODY_FRD`, `increment_f = 5.0`, `angle_offset = 0` (сектор j → j·5°,
  по часовой), 72 ячейки; вне FoV — 65535; CLEAR_MEASURED → `max_distance + 1`.
- 65535 для FC — «нет данных», не «свободно» и не запрет движения. Не называй это «свободным» в коде и логах.
- Невалидные данные никогда не снимают препятствие (MAP-13).
- Земля: проверка по угловой протяжённости зоны и по всем целям зоны (MAP-14, MAP-18); статус
  «не подтверждена до T-25/T-26» (MAP-19). Монтаж строго горизонтальный, механического наклона нет.
- Фазы — только по данным FC (`HEARTBEAT` armed, `EXTENDED_SYS_STATE.landed_state`, высота); не по таймерам.
- Успех команды удержания — только по режиму в HEARTBEAT FC, не по `COMMAND_ACK` (FLT-03).
- STM32F407/F429: аппаратный I²C максимум 400 кГц — датчики только по SPI 2–3 МГц (≥ 1,1 МГц).
- VL53L8CX ULD: использовать официальный STSW-IMG040 без изменений; свой — только platform-слой.

## 9. Порядок работы над задачей

1. Прочитай нужные разделы ТЗ и `docs/traceability.md`. Кратко изложи план (что, какие ID, какие тесты).
2. Сначала тесты по критериям ТЗ, затем код. Маленькие шаги, сборка и тесты после каждого.
3. Прогони всё: host-тесты, покрытие, cppcheck; для E3 — SITL-сценарии.
4. Обнови traceability, `CHANGELOG.md`; коммит с понятным сообщением (`core: MAP-13 cell state machine`).
   В удалённый репозиторий не пушь без просьбы.
5. Отчитайся коротко: что сделано (ID), что прошло, что нет, открытые вопросы. Без пересказа кода.

Останавливайся и спрашивай, если: нужно железо или данные о плате; требование неоднозначно;
тест ТЗ не проходит и исправление меняет поведение, описанное в ТЗ; нужна установка ПО или доступ к сети.
