# ТЗ 3.1: STM32F4 + 3×VL53L8CX → ArduPilot

Oct 23, 2026 · @Oleksandr Shunin

Модуль обнаружения препятствий для ArduCopter 4.7.2. **Окончательная редакция 3.1** заменяет редакции 1.0, 2.0 и 3.0. Учтены анализ ТЗ, два технических заключения от 23.10.2026 и решение об отказе от механического наклона датчиков. Модель платы STM32 — параметр конфигурации; требования от неё не зависят.

Изменения относительно 3.0: формулы FRD (MAP-01, MAP-02); автомат удержания и снятия препятствий (MAP-13 вместо MAP-08); проверка «луч — земля», источник высоты и автомат полётных фаз (MAP-14…MAP-17); `EXTENDED_SYS_STATE` во входящих сообщениях; R по вероятности обнаружения (SPD); раздельные метрики задержки; параметры в слотах A/B (SW-07); уточнённые тесты и новые T-25…T-27; монтаж строго горизонтальный; классификация земли по протяжённости зоны и по нескольким целям (MAP-14, MAP-18) со статусом «не подтверждена до T-25/T-26» (MAP-19); T-26 — блокирующий перед автономными полётами с BendyRuler.

## 1. Назначение, статус и границы

**Назначение.** Внешний модуль на STM32F4 объединяет измерения трёх многозонных ToF-датчиков VL53L8CX в единую переднюю карту препятствий. Карта передаётся в Cube Orange+ по MAVLink 2 как один виртуальный proximity-сенсор (`OBSTACLE_DISTANCE`). Обход выполняет штатный планировщик BendyRuler в режимах AUTO, GUIDED и RTL.

**Статус.** Исследовательская конфигурация для экспериментальных полётов. Безопасность при неполном обзоре, потере данных и дневном освещении не доказана и подтверждается только испытаниями (раздел 13). Документ не является протоколом испытаний.

**Входит в V1:**

- три VL53L8CX, горизонтальная компоновка с параметризуемыми углами;
- прошивка STM32: драйверы, управление датчиками, геометрия, оценка качества, карта, MAVLink, диагностика, реакция на собственные отказы;
- двусторонний MAVLink с FC: карта, предупреждения, телеметрия FC, команда удержания при отказе модуля;
- набор параметров ArduPilot для BendyRuler и изоляции ручных режимов;
- host-тесты, эмулятор для SITL, стендовые и лётные испытания с логами.

**Не входит в V1:**

- управление движением с STM32 (кроме перевода FC в удержание при отказе модуля — FLT-03);
- код на стороне FC (Lua-скрипты, модификация прошивки);
- круговой обзор; гарантированное обнаружение проводов, стекла, сетки, тонких и малоконтрастных объектов;
- гарантированная дальность 4 м на солнце, гарантированный обход по неполному полю зрения;
- собственный планировщик (бывший V2) — сохраняются только точки расширения интерфейсов;
- камера OV7725 в полётной сборке.

**Формат требований.** Каждое требование имеет ID (SNS, MAP, ICD, FLT, FC, SPD, DIA, SW, HW) и проверяется тестом из раздела 13. Значения с пометкой «параметр» задаются в конфигурации (раздел 15) и уточняются замерами без изменения ТЗ.

## 3. Архитектура системы

Два независимых узла: сенсорная голова на STM32 строит карту и следит за своим здоровьем, штатный FC выполняет обход и настраивается только параметрами. Связь между ними — один UART со стандартным MAVLink.

Карта идёт сверху вниз по левой колонке и попадает в базу OA, откуда её берёт BendyRuler. Телеметрия FC нужна модулю для маркировки земли и для решения о команде удержания. В V1 модуль не управляет движением.

## 5. Обработка и карта препятствий (MAP)

Вся обработка выполняется в чистом C-ядре без зависимостей от HAL (SW-02) и детерминирована: одинаковый вход даёт одинаковый выход на ПК и на МК. Датчики смотрят строго горизонтально, поэтому земля обрабатывается только логикой (5.4).

### 5.1. Системы координат и геометрия

Датчика S: x — по оптической оси, y — вправо, z — вниз. Корпуса B: FRD. Горизонтальная L: B без крена и тангажа. Азимут ψ положительный вправо, угол места ε — вверх, тангаж θ — носом вверх, крен φ — правым бортом вниз (как в ArduPilot). Для сетки N × N после `ORIENT_TRANSFORM` столбец j и строка i (i = 0 — верхняя):

```latex
\alpha_j = \left(j - \tfrac{N-1}{2}\right) \tfrac{45^\circ}{N}, \quad \beta_i = \left(\tfrac{N-1}{2} - i\right) \tfrac{45^\circ}{N}, \quad \mathbf{p}_S = r\,[\cos\beta_i \cos\alpha_j,\; \cos\beta_i \sin\alpha_j,\; -\sin\beta_i]^T
```

```latex
\mathbf{p}_B = R_z(\psi_m) R_y(\theta_m) R_x(\varphi_m)\, \mathbf{p}_S + \mathbf{t}_m, \qquad \mathbf{p}_L = R_y(\theta) R_x(\varphi)\, \mathbf{p}_B
```

ψ\_m, θ\_m, φ\_m, t\_m — параметры монтажа (θ\_m и φ\_m номинально 0, хранят измеренную ошибку установки); θ, φ — из ATTITUDE, интерполированной на момент захвата. R\_y(θ) переводит \[1, 0, 0\] в \[cos θ, 0, −sin θ\]. В карту идут d = √(x\_B² + y\_B²) и ψ = atan2(y\_B, x\_B); высота точки над землёй h\_p = h\_tof − z\_L. Дальность ULD считается измеренной вдоль луча зоны (гипотеза H-13, T-10).

### 5.2. Состояния и экспорт

| Состояние | Условие | Экспорт в `OBSTACLE_DISTANCE` |
| --- | --- | --- |
| OCCUPIED | Валидная цель (MAP-03) в `[min, max]` или удержание по MAP-13 | Горизонтальная дистанция, см |
| CLEAR\_MEASURED | Подтверждённое отсутствие цели (MAP-13) | `max_distance + 1` (для ArduPilot — «нет данных») |
| UNKNOWN | Невалидные данные, истёкшее удержание, датчик неисправен | 65535 |
| STALE | Возраст данных больше `VALID_DATA_MAX_AGE_MS` | 65535 |
| Флаг GROUND\_SUSPECT | h\_p ≤ `GROUND_TOL_M` (MAP-14) | По фазе (MAP-17) |

Значения 65535 и max + 1 для ArduPilot одинаковы: они не создают запрета движения, но и не доказывают свободу. Внутренняя семантика, LCD и логи их различают.

### 5.3. Удержание и снятие препятствия (MAP-13)

Невалидные данные никогда не снимают препятствие. Ячейка хранит: состояние, дистанцию, время последнего валидного измерения, источник (датчик, зона), признак угловой достоверности, флаг GROUND\_SUSPECT, счётчики. Кандидат из кадра: **OCC** — хотя бы одна зона даёт валидное препятствие (берётся ближайшее); **CLR** — все зоны валидны и цели до `max_distance` нет; **INV** — все остальные случаи.

| Текущее | Кандидат | Переход |
| --- | --- | --- |
| Любое | OCC ближе удерживаемой дистанции | OCCUPIED сразу |
| OCCUPIED | OCC дальше | Дистанция растёт после `DIST_RELAX_FRAMES` (2) подтверждений подряд |
| OCCUPIED | CLR | После `CLEAR_CONFIRM_FRAMES` (3) подряд → CLEAR\_MEASURED (если включено), иначе UNKNOWN |
| OCCUPIED | INV | Удержание; счётчик CLR сбрасывается; старше `HOLD_MAX_MS` (500 мс) → UNKNOWN с записью в лог |
| UNKNOWN / CLEAR\_MEASURED | INV | UNKNOWN |
| UNKNOWN | CLR | После `CLEAR_CONFIRM_FRAMES` подряд → CLEAR\_MEASURED (если включено) |

Перекрытие зон: ближайшая валидная цель имеет приоритет; невалидная зона одного датчика не отменяет препятствие другого; CLR требует согласия всех зон.

### 5.4. Земля и полётные фазы (MAP-14…MAP-17)

При горизонтальном монтаже и высоте оптики 0,20 м на стоянке землю видят две нижние строки матрицы 4×4 из четырёх: центр нижней строки (−16,9°) — на ≈0,66 м, центр второй снизу (−5,6°) — на ≈2,0 м, нижний край FoV — на ≈0,48 м. Наклон носом вниз в полёте приближает землю. Удалять строки нельзя — будут пропущены низкие предметы и рельеф, поэтому модуль определяет землю по каждому лучу и решает по фазе полёта, которую задаёт FC.

&#91;embedded content: Автомат полётных фаз (MAP-16) · 6 состояний + резерв\]

| Фаза | Вход | Точки GROUND\_SUSPECT | Реальные препятствия | Команда удержания (FLT-03) |
| --- | --- | --- | --- | --- |
| GROUND | disarmed | 65535 | Передаются | Нет |
| ARMED\_GROUND | armed, LS = ON\_GROUND | 65535 | Передаются | Нет |
| TAKEOFF | LS = TAKEOFF или IN\_AIR при h\_tof < `PHASE_H_FLIGHT_M` | 65535 | Передаются | По FLT-03 |
| FLIGHT | LS = IN\_AIR и h\_tof ≥ `PHASE_H_FLIGHT_M` (1,5 м) в течение 1 с; остаётся FLIGHT, пока LS = IN\_AIR | По `GROUND_POLICY` (KEEP — как препятствие) | Передаются | По FLT-03 |
| LANDING | LS = LANDING | 65535 | Передаются | По FLT-03 |
| GROUND\_RECOVER | LS = ON\_GROUND после полёта | Сброс автоматов ячеек, удержаний и эпизодов отказа → GROUND или ARMED\_GROUND | — | Нет |
| PHASE\_UNKNOWN | Нет HEARTBEAT или `EXTENDED_SYS_STATE` > 3 с | Как во FLIGHT (KEEP) | Передаются | По FLT-03, если режим известен |

**Допущение переходных фаз и его проверка.** 65535 не является запретом движения: `AP_Proximity_MAV` просто не создаёт препятствия в таком секторе. Поэтому политика «земля → 65535» в TAKEOFF и LANDING безопасна только при условии, что реальная траектория взлёта, посадки и перехода к горизонтальному движению в ArduCopter 4.7.2 не требует данных из исключённых зон. Это допущение (H-14) не подтверждено и проверяется **блокирующим испытанием T-26**: до его прохождения в SITL автономные полёты с включённым BendyRuler запрещены. При провале T-26 пересматривается политика экспорта в переходных фазах (что и когда передаётся), а не только порог `PHASE_H_FLIGHT_M`.

Дополнительное эксплуатационное условие: высота взлёта в миссии до первого горизонтального участка — не ниже `PHASE_H_FLIGHT_M + PHASE_H_HYST_M`, чтобы горизонтальное движение начиналось уже в фазе FLIGHT.

В фазе FLIGHT на малой высоте земля по умолчанию считается препятствием (KEEP): это консервативно и может давать ложные обходы до решения по T-22.

## 7. Отказоустойчивость (FLT)

В ArduCopter 4.7.2 нет штатной реакции на потерю proximity-данных: через 500 мс без сообщений статус PRX становится NoData, а AUTO продолжает миссию. Неизвестные сектора не создают запрета движения. Поэтому модуль сам обнаруживает свои отказы и пытается перевести FC в удержание. Это **дополнительный механизм, а не гарантированный failsafe**: непокрытые сценарии перечислены в разделе 16.

| ID | Требование | Критерий |
| --- | --- | --- |
| FLT-01 | Обнаруживаемые отказы: датчик FAILED или DEGRADED, нет объединённой карты дольше 2 × `VALID_DATA_MAX_AGE_MS`, карта LOST, потеря ATTITUDE/высоты при `GROUND_POLICY = DROP`, внутренняя ошибка (переполнение стека, исчерпание буферов). Время обнаружения ≤ 300 мс | T-07, T-14 |
| FLT-02 | При карте LOST модуль прекращает отправку `OBSTACLE_DISTANCE` (FC через 500 мс переходит в NoData), HEARTBEAT продолжается с CRITICAL | T-14 |
| FLT-03 | Команда удержания: если FC armed, режим ∈ {AUTO, GUIDED, RTL}, фаза ∈ {TAKEOFF, FLIGHT, LANDING, PHASE\_UNKNOWN}, `FAULT_ACTION` ≠ NONE и класс отказа входит в `FAULT_TRIGGER_MASK` → `MAV_CMD_DO_SET_MODE` (BRAKE или LOITER) не позже 100 мс после обнаружения. Повтор каждые 500 мс, не более 5 раз. Успех — **только** по режиму в HEARTBEAT FC; `COMMAND_ACK` фиксируется в логе, но успехом не считается | T-15 |
| FLT-04 | Эпизод отказа длится до его исчезновения. В одном эпизоде — не более одного успешного перевода. Если пилот вернул AUTO при том же отказе, модуль больше не командует, а только предупреждает. **Повторное включение AUTO при сохраняющемся отказе — осознанно принимаемый пилотом риск** (раздел 16) | T-15 |
| FLT-05 | Модуль никогда не командует: при disarmed, в фазах GROUND и ARMED\_GROUND, в режимах вне {AUTO, GUIDED, RTL}, другими командами, кроме `DO_SET_MODE` и `SET_MESSAGE_INTERVAL` | Юнит-тест + T-16 |
| FLT-06 | Отказ FC выполнить перевод (нет смены режима после всех повторов) → `STATUSTEXT` CRITICAL «TOF HOLD REJECTED» | T-15 |
| FLT-07 | IWDG с таймаутом ≤ 500 мс, BOR включён; причина сброса сохраняется и сообщается после старта | T-17 |
| FLT-08 | После рестарта: если в первом HEARTBEAT FC armed и режим ∈ {AUTO, GUIDED, RTL} → команда удержания (`FAULT_ON_REBOOT`, по умолчанию включено) и `STATUSTEXT` «TOF REBOOTED IN FLIGHT» | T-17 |
| FLT-09 | Рестарт до первой валидной карты ≤ 3 с | T-17 |
| FLT-10 | «Виртуальная стена» (`FAULT_WALL`, по умолчанию 0): сектора неисправного датчика заполняются препятствием на `min_distance`. Экспериментальная функция, включается только после T-18 в SITL | T-18 |
| FLT-11 | Сбой одной подсистемы (LCD, лог, один датчик) не останавливает остальные: основной цикл продолжает обслуживать UART и исправные датчики | T-07, T-11 |

## 9. Скорость и тормозной путь (SPD)

2 м/с — верхняя уставка ТЗ, а не безопасная скорость. Рабочая скорость определяется из измеренных величин по условию:

```latex
v^2 / (2a) + v \cdot T + M + M_{OA} \le R
```

где R — надёжная дальность для данного класса целей и освещённости, a — фактическое замедление, T — полная задержка тракта (кадр + чтение + обработка + UART + цикл OA), M — запас на погрешность, M\_OA — `OA_MARGIN_MAX`.

Иллюстрация (a = 2 м/с², T = 0,25 с, M = 0,3 м, M\_OA = 0,7 м — допущения, не свойства аппарата): R = 1,5 м → 1,0 м/с; R = 2,0 м → 1,6 м/с; R = 2,5 м → 2,0 м/с.

**Определение R.** Наибольшая дальность, до которой во всех интервалах по 0,25 м вероятность обнаружения Pd ≥ 0,95 (не менее 5 независимых установок цели по 50 кадров), а ложных срабатываний не больше `FAR_MAX` (стартовое — 1 на сектор за 10 мин). Pd — доля кадров, где ячейка с целью OCCUPIED с ошибкой не более max(5 см, 5 %). R определяется отдельно для каждого класса целей (светлая матовая, тёмная матовая, растительность; металл/стекло — для фиксации пропусков) и освещённости (помещение, тень, прямое солнце, со значением люксметра).

**Задержка T** = период кадра (экспозиция) + (t5 − t1) по p99 + цикл OA на FC (MAP-12, T-11).

| ID | Требование | Критерий |
| --- | --- | --- |
| SPD-01 | Измерить: R по определению выше; T по отметкам t1…t5; a — торможение в свободном полёте с полезной нагрузкой | T-10, T-11, T-20, T-23 |
| SPD-02 | Рабочая скорость `WPNAV_SPEED` / `RTL_SPEED` = min(2 м/с, решение условия выше) для худшего допускаемого условия эксплуатации. Если решение < 0,5 м/с — автоматический обход в этих условиях запрещается | Акт T-23 |
| SPD-03 | Таблица «условия → R → допустимая скорость» входит в ограничения применения (раздел 16) | Ревью |
| SPD-04 | Дополнительно к R фиксируются: время первого устойчивого обнаружения (3 кадра), смещение и СКО дальности, доля валидных зон, пропуски кадров | T-10, T-20 |
| SPD-05 | Адаптивное ограничение скорости модулем (`MAV_CMD_DO_CHANGE_SPEED`) — вне V1 | — |

## 11. Программная архитектура и ресурсы (SW)

Прошивка делится на чистое ядро (вся логика, тестируется на ПК), тонкий слой платы и неизменённый драйвер ST. Модель платы влияет только на `bsp/<board>/` и конфигурацию выводов.

Структура репозитория:

```
tof_avoid/
  CMakeLists.txt, CMakePresets.json   # host, target-<board>
  core/        # C11 без HAL: geometry, quality, fusion, classify, ground,
               # mavlink_tx/rx, fault_fsm, events, params, scheduler
  bsp/         # bsp.h — интерфейс; bsp/<board>/ — реализация + board_pins.h
  drivers/     # vl53l8cx_platform.c (ULD через bsp), lcd_<model>.c
  third_party/ # ST ULD (без изменений), mavlink c_library_v2, Unity
  app/         # main.c, связывание ядра и BSP, сборки DEBUG/FLIGHT
  tests/host/  # юнит-тесты ядра
  tools/       # emulator/ (pymavlink + SITL-сценарии), logdecode/, scripts/
  params/      # fc_tof_v1.param, module_defaults.json
  docs/        # ICD, ограничения, протоколы испытаний
```

## 14. Этапы разработки и роли

Этапы E0, E1 и E3 не требуют железа и не зависят от модели платы — агент начинает с них. E2 стартует, когда известна плата; E3 можно вести параллельно с E2 и E4.

## 16. Ограничения применения и непокрытые риски

Без независимого контроля на стороне FC полный отказ внешнего модуля **остаётся неустранённым**. V1 эксплуатируется с этим ограничением; закрыть его можно только кодом на FC, что в V1 исключено.

| Сценарий | Реакция модуля | Остаточный риск |
| --- | --- | --- |
| Отказ одного датчика | Диагностика, попытка BRAKE/LOITER | FC может отклонить команду |
| Потеря достоверности карты (засветка, деградация) | Предупреждение, попытка удержания | Нет надёжной карты до реакции |
| Зависание МК → IWDG | Рестарт ≤ 3 с, команда удержания после рестарта | Окно без измерений до ≈3,5 с |
| Плохая оценка положения FC | Диагностика | BRAKE/LOITER могут быть недоступны |
| Пилот повторно включил AUTO при сохраняющемся отказе | Только предупреждения (FLT-04) | Осознанно принимаемый пилотом риск |
| Обрыв UART | Команда не дойдёт | FC продолжает AUTO без обхода |
| Полное обесточивание модуля | Нет | FC продолжает AUTO без обхода |
| Препятствие вне FoV | Нет данных | BendyRuler может выбрать путь в ненаблюдаемый сектор |
| Низкие предметы высотой меньше `GROUND_TOL_M` в наземных фазах | Не передаются (MAP-17) | Допустимо, пока аппарат не движется горизонтально |
| Полёт на малой высоте (FLIGHT, KEEP) | Земля передаётся как препятствие | Ложные обходы или остановки до решения по T-22 |
| Тонкие, прозрачные, сетчатые, тёмные объекты | Возможен пропуск | Столкновение |

**Условия, при которых автоматический обход запрещён** (вносятся в акт после E7–E8):

- освещённость или классы целей, для которых R не измерена или скорость по SPD-02 < 0,5 м/с;
- полёт с `FAULT_ACTION = NONE`;
- неподтверждённая версия прошивки FC или изменённые параметры FC относительно `params/fc_tof_v1.param`;
- отсутствие годной оценки положения FC;
- любые незакрытые провалы тестов T-11…T-17;
- T-26 не пройден в SITL — автономные полёты с BendyRuler запрещены полностью; не пройден в полёте — запрещены рабочие миссии;
- высота взлёта в миссии до первого горизонтального участка ниже `PHASE_H_FLIGHT_M + PHASE_H_HYST_M`;
- до прохождения T-25 и T-26 различение земли и низких препятствий не подтверждено (MAP-19): `GROUND_POLICY = DROP` запрещён, низкие препятствия у земли считаются потенциально необнаруживаемыми.

**Обязательная процедура оператора:** перед полётом проверить «TOF READY» и PRX Good в GCS; в полёте держать управление готовым к перехвату; `RCx_OPTION = 40` — для немедленного отключения обхода.
