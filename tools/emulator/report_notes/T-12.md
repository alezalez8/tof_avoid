**Результат.** Оба подпункта проходят: кодирование `OBSTACLE_DISTANCE` по таблице раздела 6 (ICD-01), один пакет на кадр
карты с частотой `MAV_DISTANCE_RATE_HZ` = 10 Гц и без потерь между модулем и FC (ICD-02), сектора вне FoV — 65535,
max + 1 при включённом CLEAR_MEASURED принимается FC за «нет препятствия» и не создаёт точек в базе OA, PRX — Good.

**H-10 подтверждена.** В ArduCopter 4.7.2 есть prearm-проверка proximity (`AP_Proximity::prearm_healthy`,
`AP_Arming.cpp`): без модуля взвод отклоняется с «Arm: PRX1: No Data», PRX Good появляется через ≈ 0,2 с после запуска
модуля. Следствие для процедуры раздела 16: проверка «PRX Good» перед полётом выполняется самим FC.

**Углы.** Значение зоны распространяется на всю её угловую протяжённость (MAP-05: 11,25° + `CAL_TOL_DEG` = 2° с каждой
стороны, без интерполяции), поэтому столб радиусом 0,15 м занимает 7 секторов (±15° от истинного азимута), а ближайший
сектор — сектор истинного азимута. FC повторяет это без сдвига и зеркалирования: грани proximity FC совпадают с гранями,
вычисленными из пакета по правилам `AP_Proximity_MAV` (±5 см с учётом фильтра `PRX_FILT`); `CAn` в журнале PRX — первый
сектор с минимумом внутри следа (315° для столба на −30°), а не его центр.
